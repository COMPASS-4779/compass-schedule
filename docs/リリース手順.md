# リリース手順（課題送信システム・スケジュール管理）

テスト作成システム（compass-test-generator の docs/リリース手順.md）と同じ流れ。

| ブランチ | 環境 | 確認URL |
|---|---|---|
| `develop` | テスト環境（Render: compass-schedule-dev、ENVIRONMENT=development） | `<テスト環境のURL>/health` |
| `main` | 本番（Render: compass-schedule-api） | https://compass-schedule-api.onrender.com/health |

## テスト環境の設定（Render の環境変数）
- `ENVIRONMENT=development`（LINE・メールを送らない）
- `DATABASE_URL`: テスト用の PostgreSQL（本番のDBは使わない）
- Google（Drive・結果シート）を試すときだけ: テスト用の `HW_DRIVE_PARENT_FOLDER_ID`・`HW_RESULT_SPREADSHEET_ID` を入れて `STAGING_GOOGLE_OK=1`
- `TESTGEN_URL`: テスト作成システムのテスト環境（https://compass-test-generator-stg.onrender.com）
- LINE の Webhook は本番に向いたまま（テスト環境には届かない）

## ふだんの修正
1. `develop` から作業ブランチ → PR を `develop` へ → テスト環境に自動で出る
2. テスト環境の `/health` で `commit` を確かめ、変更を確かめる
3. 先生に報告し、**OKをもらうまで本番に出さない**

## 本番に出す（先生のOKのあと）
1. `VERSION` と `CHANGELOG.md` を更新（develop 上）
2. PR `develop → main` をマージ → 本番の `/health` の `version`・`commit` を確かめる（起動時にDBのバックアップ `release` が自動で取られる）
3. `gh release create v… --target main` で版を記録 → 先生に報告

## 戻し方
1. 急ぎ: Render の Rollback（または compass-test-generator の `tools/render_rollback.py rollback compass-schedule-api`）
2. 特定の変更・版ごと: 取り消す PR を作り、テスト環境で確かめてから本番へ
3. 「データ変更あり」の版を戻すとき: Google Drive「バックアップ_課題送信DB」の、その版の `release` から
   `python tools/restore_db.py <ファイル> --tables <テーブル>` で戻す（先に今のDBのバックアップを取る）。
   Render の PostgreSQL 自体のバックアップ（有料プランの日次）も使える。

## データの決まり
- テーブル・列は「足すだけ」。消したり意味を変えたりしない（古い版に戻しても動くように）。
